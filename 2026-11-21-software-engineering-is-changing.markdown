I wrote a blog post only a few months ago called ["SWEs Are Not Going Anywhere"](https://www.twelventi.com/posts/2026-05-25-swes-are-not-going-anywhere). The main point of this article still stands, however there needs to be an updated assessment. 

DHH, the creator of Ruby on Rails, proclaimed in a [in a talk at Rails World 2026](https://x.com/thedealdirector/status/2103104430216557055) that "the days of chiseling code by hand are over". The word choice here "chiseling" is a phenomenal analogy in my opinion, because it is a real parallel to how engineers used to interact with code. The results of countless hours of finding where you forgot to type a semi colon, and hammering out letter by letter instructions to the software you are developing, can now be achieved by one simple prompt and a little bit of patience. Of course, the point in my last article still stands that you need to know what and how to prompt your agents, but the time it takes to produce code from an idea is trending towards zero. 

Agents are capable of taking an obtuse error message, reading the code to figure out how it surfaced, and producing a fix for a bug, or an explanation to how it occurred. If you have a proper agent harness and agent loop, your software can automatically heal itself (with, if necessary, input from a human). 

No longer do you need to wrestle with a seed-phrase.txt file, for example, figuring out how to orchestrate parameters to a `cast` call to experiment sending a certain transaction to the blockchain. You simply can say "hey cursor, my seed phrase is at ~/seed.txt, can you find the second BIP32 derivation from the seed and lmk how much ETH I have in this wallet?".

If your job as a software engineer before was solely regurgitating and implementing the minutiae of a ticket exactly as described, with no foresight or suggestions about how to improve the system you are working on over all, your work can likely be done by AI. If, however, you are an engineer who understands how the system works, why software was designed in a certain way, AI can make you a 1000x engineer. 

Imagine if you, as a software engineer, had a team of 10,000 developers who can implement anything you ask almost instantly. Orchestrating these implementations, and asking for the correct things is the new role of a software engineer. At a fundamental level, a very good software engineer is not someone who knows tons of libraries, it's someone who is a good problem solver. You are still a problem solver, and you are still engineering software, but now you basically have access to infinite productivity.

From when you were first learning to code and even until now, your subconscious must've been thinking about random things that you would want to build, planning them out in your head, but never getting around to building them because you lack the time. Now considering the velocity at which AI can produce code, you have enough time to build any and everything you ever wanted. This is the new bleeding edge, and the time to build is now. 

Ensure that your agents are setup in a way that can respond to your requests without friction and can self-heal when things go wrong. If you are despairing at the future, don't, because there has never been a cooler time to be a software engineer. If you don't believe me about the power of how AI can help you, especially when they can self heal and respond to each other, go download grok bots, with practically no effort you can immediately have an MVP of anything you ever could think to build.
